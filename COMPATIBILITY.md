# Совместимость ADAMO GT

Версия 2.7.1 добавляет упрощённую отправку в CRM: пароль, количество и состояние. Кнопка скрыта до подтверждения офисного доступа сервером. Снимок первой страницы и характеристики готовятся автоматически; склад и принтер задаются в CRM. Для работы требуется настроенная серверная интеграция. Сохранены выбор объёма RAM без прежнего ограничения 2 GB, существующие источники температур LibreHardwareMonitor/PawnIO и Windows/производителя и исправления камеры. Экспериментальный AdamoThermal исключён из исходников и пакета; старый параметр `--adamo-thermal` игнорируется. Сведения о портах при запуске берутся из локального справочника или кэша; интернет-поиск выполняется по кнопке после согласия пользователя. Проверка доступности CRM отправляет только обычный сетевой запрос, без отчёта об оборудовании. Подпись SignPath Foundation ещё не получена.

Приложение предназначено для быстрой проверки компьютера. «Нет данных» означает, что конкретный BIOS, контроллер, драйвер или Windows не предоставил показатель. Это не диагноз неисправности.

## Выбор объёма RAM в версии 2.6.5

- По умолчанию выбран «Авто»: до 80% доступной физической памяти с резервом не менее 1 GB. Можно выбрать верхнюю границу 2, 4, 8, 16, 32 или 64 GB; если столько безопасно выделить нельзя, объём уменьшается. Прежний общий предел 2 GB удалён. Ограничения commit и адресного пространства учитываются отдельно.
- При выделении показываются целевой и уже выделенный объёмы; в ходе проверки — объём, прошедший все три шаблона. Эти значения сохраняются в JSON вместе с результатом, включая отмену и ошибки. Большому объёму может потребоваться больше времени для полного цикла.
- Резерв, рассчитанный перед запуском, перепроверяется перед каждой операцией с блоком. Память, занятая Windows и другими приложениями, не проверяется. Режим не обещает полный охват установленной RAM.
- Перед выделением каждого блока повторно проверяются лимит commit и доступное адресное пространство с резервом 256 MB. После завершения или отмены пула от 256 MB вызывается сборка мусора для освобождения больших массивов до повторного запуска; интерфейс может кратковременно приостановиться во время очистки.

## Исправления RAM в версии 2.6.4

- Для каждого из трёх шаблонов сначала записывается вся выделенная область, затем отдельно проверяется. Это уменьшает влияние немедленного чтения только что записанного блока из кэша CPU.
- «Циклов» теперь означает полные проходы всех трёх шаблонов по всем выделенным блокам. Отдельно показываются выделенный объём, охват всеми шаблонами и число проверенных блоков. Если время закончилось до первого полного цикла, результат сообщает о незавершённой проверке.
- Доступная физическая память повторно проверяется перед каждым блоком записи/чтения, а не только при выделении. При потере резерва 1 GB для Windows тест останавливается. Отмена проверяется внутри циклов обработки.
- В версии 2.6.4 сохранялся предел 2 GB и четверть доступной физической памяти; в 2.6.5 он заменён выбором объёма, описанным выше. Windows, кэш процессора и подкачка остаются активны; это не полная проверка всей установленной памяти и не замена диагностике вне Windows.

## Подготовка 2.6.1: камера и температуры

- Камера: вместо зависимого от старых видеодрайверов стандартного DirectShow renderer используется вывод полученных RGB-кадров через GDI. Проверяются поддерживаемые драйвером форматы, наличие кадров и их дальнейшее поступление. Отсутствие кадров не считается успешным запуском; тёмное изображение сопровождается подсказкой, но не автоматическим диагнозом камеры. Буферы остаются только в оперативной памяти.
- На iMac/Mac с Windows необходим подходящий драйвер камеры из Boot Camp Windows Support Software. Если камера не показывает изображение и в штатном приложении Windows, исправление предпросмотра ADAMO GT не заменяет драйвер. [Рекомендация Apple](https://support.apple.com/en-ie/guide/bootcamp-control-panel/bcmpe4bfee38/mac).
- GPU: дополнительное чтение температуры через Windows WDDM по идентичности адаптера. Доступность зависит от установленного видеодрайвера; отдельный PawnIO для этого пути не требуется.
- CPU: используются явно обозначенные производителем CPU-датчики, доступные через WMI. Это может быть датчик производителя около CPU, а не температура кристалла; источник показывается отдельно. Данные общего ACPI Thermal Zone не выдаются за температуру CPU. Если подходящего источника нет, значение остаётся неизвестным.
- PawnIO остаётся необязательным способом расширить доступ. Универсальное получение температуры CPU без дополнительного драйвера на всех компьютерах не гарантируется. Программа не устанавливает драйверы автоматически, не подставляет приблизительные температуры и не отключает защиту Windows.

## Стресс-тесты в версии 2.6.0

- «Стресс» → галочки CPU/RAM/SSD/GPU → 1, 5, 10 или 15 минут → «Начать». По умолчанию нагрузки одновременные; «По очереди» задаёт указанное время каждому выбранному тесту. Автозапуска стресс-тестов нет.
- CPU: вычисления с контрольными значениями, до 64 логических процессоров. RAM: запись и проверка шаблонов в выделенной части памяти, максимум 2 GB и четверть доступной физической памяти, с резервом для Windows. Это не проверка всей установленной RAM.
- SSD: собственный временный файл до 256 MB на проверенном фиксированном томе NTFS/ReFS, плюс 1 GB свободного резерва. После 8 GB записи нагрузка продолжает чтение и проверку. Проверяются записанные данные; пользовательские файлы не используются. Смена устройства и неоднозначная принадлежность тома блокируют запуск.
- GPU: аппаратный D3D11 feature level 11_0, проверка ответов устройства и достоверности timestamps. Это не полная проверка VRAM или правильности каждого пикселя.
- Свежие показания соответствующих датчиков останавливают всю сессию при CPU ≥ 95 °C, GPU ≥ 90 °C, SSD ≥ 70 °C. При RAM-тесте также контролируется температура CPU. Неизвестные и устаревшие температуры не дают защиты по температуре. Пределы фиксированные, не индивидуальная спецификация каждого процессора.
- Ошибка или «Остановить» отменяет нагрузки. Окно ждёт окончания операций и освобождения ресурсов; при зависшем стороннем драйвере это ожидание может затянуться. Повторный запуск до очистки недоступен.
- Итоги текущего запуска приложения, включая отмену и доступные пиковые температуры, попадают в JSON-отчёт отдельно от сохранённых замеров скорости. Успешное завершение означает отсутствие обнаруженных ошибок данной нагрузки, а не гарантию исправности компьютера.

## Проверка устройств в версии 2.5.1

- Кнопка «Устройства» открывает ручные проверки камеры, микрофона, клавиатуры и динамиков. Они не запускаются автоматически вместе с SSD/GPU.
- Камера: выбор устройства Windows и живое изображение через DirectShow. Видеозапись и сохранение фотографий отсутствуют. Камеры без совместимого драйвера DirectShow, отключённые разрешения Windows, закрытая шторка или занятое устройство могут препятствовать просмотру.
- Микрофон: запись до 5 секунд в оперативной памяти, индикатор сигнала и отдельное прослушивание. Требуется PCM-формат, поддерживаемый аудиодрайвером. Запись не сохраняется в файл и не передаётся по сети; при закрытии окна её буфер очищается.
- Динамики: короткие сигналы отдельно слева и справа через выбранный звуковой выход. Громкость Windows не меняется. Моноустройства, пространственные эффекты, микшер и драйвер могут смешивать каналы; пользователь оценивает фактический звук.
- Клавиатура: тест начинается при выборе вкладки и возобновляется при возвращении в окно, сохраняя отмеченные клавиши. Захват действует только при фокусе в области клавиатуры. Esc завершает захват; «Продолжить» возобновляет его. Fn и некоторые служебные/мультимедийные клавиши могут не передаваться Windows; отсутствие их событий не доказывает неисправность.
- «Работает»/«Проблема» — ручное подтверждение пользователя с датой и именем устройства. Старое подтверждение явно отделено от текущего состояния: замена периферии не переносит автоматически диагноз на новое устройство. Сохраняются только итог и метаданные, не изображения, звук или последовательность нажатий. История устройств не меняет маркер автоматических тестов SSD/GPU.
- Автоматические регрессии используют подставные устройства и сигналы. Дополнительная проверка реального оборудования запускается только явно: `tests/live/Test-LivePeripherals.ps1 -ActivateHardware`. Она временно включает камеру, записывает и воспроизводит микрофон, подаёт короткие сигналы в оба канала; сохраняет только числовую диагностику. Качество изображения, звука и физических клавиш требует ручной проверки на целевом компьютере. Тайм-ауты ограничивают ожидание интерфейса, но не могут принудительно завершить зависший вызов стороннего драйвера.

Основы взаимодействия с Windows: [предпросмотр DirectShow](https://learn.microsoft.com/en-us/windows/win32/directshow/previewing-video) и [владение аудиобуферами WinMM](https://learn.microsoft.com/en-us/windows/win32/multimedia/audio-data-blocks).

## Системные требования

- Текущая сборка: Windows x64, .NET Framework 4.8 или 4.8.1. Целевые системы — Windows 10 версии 1803 и новее, Windows 11. На старых выпусках Windows 10 может требоваться установка .NET Framework 4.8. Это граница используемых компонентов, а не подтверждение испытаний на каждой версии Windows.
- Реальная аппаратная проверка проведена на Windows 11, HP ZBook Firefly 14 G9, Intel Core i7-1280P / Iris Xe / WD SN810 NVMe. Остальные сочетания требуют проверки на соответствующих компьютерах.
- Windows x86 и Windows on ARM не входят в подтверждённую поддержку этой сборки. Для ARM нужна отдельная проверка всех нативных компонентов и доступа к датчикам; запуска x64-программы через эмуляцию недостаточно.
- Основные характеристики доступны без прав администратора. Для части температур необходимы установленный PawnIO и запуск с повышенными правами. Установка драйвера выполняется только через соответствующую кнопку и стандартный запрос Windows.
- GPU-тест требует аппаратного Direct3D feature level 11_0. Программный рендерер не используется для оценки скорости видеокарты.
- Тест диска требует доступного фиксированного тома NTFS/ReFS, места для файла 1 GB и ещё 1 GB резерва. Автоматический запуск предусмотрен только при первой проверке компьютера; следующие запуски используют историю, повторение — кнопкой. Съёмные флешки, сетевые и неоднозначно сопоставленные тома пропускаются. Поддержка SMART зависит от контроллера и USB-переходника.
- Интернет нужен для поиска официальных спецификаций портов; локальные характеристики и тесты работают без него.

## Исправления версии 2.3

- Тип накопителя сопоставляется через номер диска Windows и уникальный идентификатор; номера разных провайдеров больше не считаются взаимозаменяемыми. Для RAID и Storage Spaces тип физических носителей не угадывается.
- Перед тестом проверяются текущая принадлежность тома выбранному диску и, когда доступен, идентификатор устройства. При выборе раздела учитывается свободное место. Старые результаты удаляются при изменении идентичности устройства по тому же индексу.
- GPU выбирается по LUID в свежем списке DXGI, даже если Windows поменяла порядок адаптеров. Несопоставленное имя датчика не создаёт дополнительную видеокарту рядом с уже найденными DXGI-адаптерами.
- «Обновить» заново получает состав оборудования, экраны и режимы. Во время тестов полное обновление откладывается до их завершения; обычные показания продолжают обновляться.
- Окно учитывает доступную рабочую область. При размере меньше 960 × 680 логических пикселей весь экран программы пропорционально уменьшается; блоки и кнопки остаются доступными.
- Для LPDDR не используется универсальный расчёт такта как половины скорости передачи. При неполных сведениях о массивах RAM число свободных слотов и общий предел памяти не подставляются.
- Ёмкости нескольких батарей суммируются только при полном согласованном наборе данных. Общая сохранённая ёмкость не смешивается с процентом износа одной батареи.
- Автономность — сценарная оценка от полного заряда: текущая полная ёмкость в Вт·ч делится на условные 15 и 7 Вт. Предположение относится к лёгкой работе, не является измерением расхода и не использует заводскую ёмкость вместо неизвестной текущей. Для 31,937 Вт·ч результат составляет примерно 2,1–4,6 часа.

## Изменения версии 2.4.0

- При каждом обычном запуске приложение запрашивает права через штатный UAC Windows, независимо от наличия PawnIO. Если права уже есть, повторного запроса нет. Отмена запроса оставляет приложение доступным без повышения прав. Служебные пробы не запрашивают права без явного `--elevate`.
- CPU/GPU имеют отдельное объяснение доступности температуры. Для CPU выбирается датчик пакета или физического кристалла; температура ACPI, расстояние до TjMax и температура CPU не подставляются вместо других датчиков. Для текущей Iris Xe драйвер не предоставляет отдельную температуру GPU.
- Текст и подписи увеличены, второстепенный текст стал темнее, отключённые кнопки сохраняют читаемый контраст. Заголовки сокращены до CPU / RAM / GPU.
- У эмблемы прозрачный фон, убраны белая подложка и большие внешние поля. ICO содержит размеры 16, 24, 32, 48, 64, 128 и 256 пикселей.
- Закрытие окна ограничивает ожидание фоновых задач восемью секундами после запроса отмены. Зависший вызов драйвера больше не удерживает окно бесконечно. Это не добавляет тайм-аут внутрь самого драйвера; изоляция аппаратных провайдеров остаётся отдельным направлением развития.
- На очень маленьких окнах содержимое по-прежнему пропорционально уменьшается. Для комфортного чтения рекомендуется доступная область не меньше 960 × 680 логических пикселей; полное вмещение при 832 × 500 не означает такой же размер текста.

## История тестов и проверка версии 2.4.1

- При первой проверке компьютера сначала показываются характеристики, затем по очереди выполняются доступные тесты SSD и GPU. Последующие обычные запуски показывают сохранённые результаты и дату каждого теста без новой автоматической нагрузки. Инвентарь, температуры, SMART и батарея читаются заново.
- История общая для компьютера, а не только для текущего профиля Windows: `%PROGRAMDATA%\ADAMO GT\History\<хеш-идентификатора-компьютера>.json`. Она отделена от распакованных компонентов в `%LOCALAPPDATA%\ADAMO GT\Runtime`. Доступ без повышения прав зависит от разрешений Windows; ошибка чтения или сохранения сообщается в приложении.
- На уже проверенном компьютере новые комплектующие и изменения конфигурации не запускают нагрузку автоматически. Несовместимые прежние результаты не подставляются; новое измерение запускается кнопкой.
- Результат SSD восстанавливается только при доступной подтверждённой физической идентичности. Неизвестная серия/идентификатор не заменяется совпадением названия и номера диска. GPU сопоставляется по аппаратной модели, без серийного номера; замену на другой экземпляр той же модели невозможно надёжно отличить. После такой замены нужен ручной тест. Неоднозначное соответствие нескольких GPU не используется.
- Ручной повтор меняет результат соответствующего устройства. Отмена или ошибка сохраняет прежнее успешное измерение с его настоящей датой; результат не объявляется новым. Неподдерживаемый GPU не заставляет приложение снова автоматически проверять SSD при следующем запуске.
- Повреждённая, недоступная или занятая история не запускает автоматические тесты. Характеристики остаются доступны, а повторное измерение запускается вручную.
- Подвал содержит текст **Creat cu ❤️ în Moldova | ADAMO.MD**. Результаты автоматических и аппаратных проверок финального пакета записаны отдельно в `TEST-REPORT-2.4.2.md`; испытания логики не заменяют проверку на физическом устройстве.

## Исправление запуска единого EXE в 2.4.2

- В кандидате 2.4.1 обнаружена ошибка повышения прав внутреннего EXE из кэша: Windows могла сообщить, что путь или файл не найден. Повышение прав внешнего единого EXE работало. Теперь запрос UAC выполняется внешним запускателем до распаковки компонентов, с общей логикой отмены и предотвращением повторного запроса.
- До этого исправления прошли 65 групп проверок приложения и восемь групп запускателя. В административной аппаратной пробе 2.4.1 получены 59 °C CPU, 3 848,3 MB/s чтения, 4 269,4 MB/s записи и 176,31 FPS GPU; код завершения — 0. Следующая проба восстановила результаты из общей истории с прежними датами тестов, а температура CPU была прочитана заново: 49 °C.
- Механизм SSD/GPU-тестов не изменён исправлением порядка UAC. Прежние измерения не объявляются новыми результатами 2.4.2. Итоговая проверка UAC, восстановления истории и содержимого пакета 2.4.2 фиксируется в `TEST-REPORT-2.4.2.md`; наличие этого раздела не заменяет подтверждающий результат проверки.

## Подтверждённые ограничения текущего компьютера

- В административной пробе 2.4.1 получено 59 °C от датчика CPU Package; при последующем восстановлении истории — 49 °C. Более ранние пробы 2.4.0 показывали 48 и 58 °C; это разные измерения. Текущий драйвер Intel Iris Xe не предоставляет отдельную температуру GPU даже при работающем IGCL. Приложение показывает причину, а не температуру CPU под видом GPU.
- Для установленного экрана AUO7A99 прочитан корректный EDID, но точная официальная связь с паспортом панели не подтверждена. У этой модели HP существуют варианты одинакового разрешения с разной яркостью; тип матрицы и ниты остаются неизвестными. Подробности источников и проверки приведены в `COMPLETION-PLAN.md`; `data/panels.json` не заполняется догадками.

## Следующие приоритеты

1. Испытания на AMD/Radeon, NVIDIA и гибридных ноутбуках, Intel разных поколений; минимум одна SATA SSD, HDD и SSD через разные USB-мосты. Отдельно — машина без батареи, с двумя батареями, с распаянной RAM и с неполными данными SMBIOS.
2. Изоляция медленных аппаратных провайдеров в отдельном процессе с ограничением времени, чтобы зависший WMI/драйвер не останавливал обновление остальных показателей. Ожидание при закрытии уже ограничено восемью секундами; это отдельная гарантия, не тайм-аут внутри каждого драйвера.
3. Расширение каталога точных моделей и панелей с источником и датой проверки. Матрица, ниты и максимальная RAM зависят от комплектации; по похожему названию их подставлять нельзя.
4. Получение сложных конфигураций экранов через QueryDisplayConfig: док-станции, дублирование, дробная частота 59,94 Гц. Проверка переходов между мониторами с разным DPI, сна/пробуждения, RDP и виртуальных машин.
5. Отдельные сборки и испытания для ARM64, если эта платформа нужна. Поддержку 32-битной Windows оценивать отдельно от основной x64-сборки.
